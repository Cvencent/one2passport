# Codex 桥接托盘程序（Windows）

把 Codex 桥接做成一个**常驻系统托盘的 EXE**，状态一眼可见，不用开着黑窗口。

---

## 一、怎么用

### 首次

1. 双击 `CodexBridge.exe`。
   任务栏右下角出现一个小图标（蓝色 = 正在启动）。
2. **右键该图标 → 「配对设备…」**。
   程序会广播查找设备并完成配对，成功后图标变**绿色 = 已连接**。
3. 完成。之后图标常驻，关掉窗口不影响它运行。

> 配对的**前提**：设备已连上 Wi-Fi（设备端：设置 → Wi-Fi → 让它连你家的 2.4GHz 网络），
> 且电脑与设备在同一网段。若还没配网，先做这一步，否则程序找不到设备。

### 日常

图标就是状态。**鼠标悬停**能看到详细文字，**右键**能操作。

---

## 二、状态含义

| 图标颜色 | 状态 | 含义 |
| --- | --- | --- |
| 🔵 蓝色 | 正在启动 / 正在连接 | 正在启动 Codex 或查找设备 |
| 🟢 绿色 | **已连接** | 一切正常，待命中 |
| 🟠 橙色 | **工作中** | 正在录音 / 识别语音 / Codex 跑任务 / 等你审批 |
| 🔴 红色 | 连接异常 | 连不上或出错，**会自动重连** |
| ⚪ 灰色 | 已停止 / 未配对 | 见悬停文字 |

悬停提示形如：

```
Codex 桥接 · 已连接
已连接 192.168.1.23:8765
已处理 7 个任务
```

---

## 三、右键菜单

| 菜单项 | 作用 |
| --- | --- |
| **配对设备…** | 广播查找设备并完成首次配对（换设备、重装后用它） |
| **立即重连** | 手动触发一次重连（一般不用点，断线会自动重连） |
| **打开日志目录** | 打开 `%LOCALAPPDATA%\FoloOS\CodexBridge`，出问题时看 `bridge.log` |
| **开机自动启动** | 打勾即随 Windows 登录自动启动（写入注册表 `HKCU\...\Run`） |
| **查看当前配置** | 显示设备地址、配对密钥、Codex 工作目录、日志路径 |
| **退出** | 完全退出（双击图标同样退出） |

---

## 四、开机自启

右键菜单里勾选「开机自动启动」即可。它写入的是**当前用户**的注册表项：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
  FoloOSCodexBridge = "<EXE完整路径>"
```

取消勾选即删除该项。不写系统级注册表，不需要管理员权限。

---

## 五、日志

```
%LOCALAPPDATA%\FoloOS\CodexBridge\bridge.log
```

超过 2MB 自动轮转为 `bridge.log.1`，不会无限增长。

**为什么一定要有日志**：EXE 是以 GUI 模式打包的，没有控制台，
程序内部所有 `print` 都会写进这个文件。程序"闪一下就没了"或"图标不变色"时，
第一件事就是看它。

## 六、排障

| 现象 | 原因与处理 |
| --- | --- |
| 图标一直是灰色「未配对」 | 点「配对设备…」。若仍失败：确认设备已连 Wi-Fi、与电脑同网段、路由器没开访客网络隔离 |
| 图标红色「连接异常」 | 程序会自动重连。持续红色就点「打开日志目录」看 `bridge.log` 里的具体错误 |
| 配对时提示"设备连上了但没有回包" | 设备**已配对过**，本次带来的密钥与设备里存的不一致。这是 TOFU 的预期行为，详见下节 |
| 双击没反应、图标不出现 | 看 `bridge.log`；若日志也没有，可能是杀软拦截，把 EXE 加白名单 |
| 语音识别总失败 | 悬停提示会显示原因。多为缺中文语音包：Windows 设置 → 时间和语言 → 语言和区域 → 给中文安装"语音" |
| 找不到 Codex | 托盘会提示。程序会自动扫 `%LOCALAPPDATA%\OpenAI\Codex\bin\<版本哈希>\codex.exe`，无需加 PATH |

## 七、关于配对（TOFU）

本工程设备端的配网页由 `esp-wifi-connect` 提供，是**固定表单**（只有 SSID 和密码），
无法像 FoloOS 原版那样在表单里附加自定义 token。所以设备端改成了
**TOFU（首次信任配对）**：

- 设备本地没有密钥时 → 接受电脑端带来的**第一个**合法密钥（≥16 字符）并永久保存；
- 配对**之后** → 必须严格匹配，不再接受新密钥。

所以「配对设备…」按钮：

- **全新设备** → 直接点，一路成功；
- **已配对过** → 需要用设备里存的那个密钥。若你之前用过 USB 串口配网脚本
  （`windows_wifi_setup.ps1`），那个脚本下发的密钥就是设备里存的，
  可直接复用 `%LOCALAPPDATA%\FoloOS\bridge.json`，**不必重新配对**。

## 八、从源码运行（不想用 EXE 时）

```bash
cd windows-client/runtime
python tray_app.py
```

依赖：`pystray`、`pillow`（已随本包用 PyInstaller 打进 EXE，源码运行需自行安装）。

---

## 九、重新打包

改了 `tray_app.py` 之后：

```bash
cd windows-client/runtime
python _gen_ico.py                              # 重新生成图标(可选)
python -m PyInstaller --noconfirm --clean CodexBridge.spec
# 产物: dist/CodexBridge.exe
```

打完后建议跑一遍自检：

```bash
python _check_tray.py     # 导入链 + 状态机
python _smoke_exe.py      # 启动 EXE,验证托盘窗口真的创建
python _e2e_exe.py        # 假设备 + 真 EXE,验证连接全链路
```

> `_e2e_exe.py` 会临时写 `%LOCALAPPDATA%\FoloOS\bridge.json` 指向 `127.0.0.1`，
> 测试后**记得删掉该文件**，否则真实使用时程序会去连本机。

## 十、与原命令行版的区别

| | 命令行版 `windows_bridge.py` | 托盘版 `CodexBridge.exe` |
| --- | --- | --- |
| 界面 | 黑窗口 | 系统托盘图标 |
| 状态 | 看文字滚动 | 图标颜色 + 悬停文字 |
| 停止 | Ctrl+C | 右键 → 退出 |
| 配对 | 另跑 `pair_device.py` | 菜单里点一下 |
| 开机自启 | 需手动配计划任务 | 菜单里勾选 |
| 依赖 | 需装 Python | **无需 Python** |

两者**共用** `%LOCALAPPDATA%\FoloOS\bridge.json`，可以随时切换。
**建议只跑一个**——两个同时跑会争抢同一个设备连接。
